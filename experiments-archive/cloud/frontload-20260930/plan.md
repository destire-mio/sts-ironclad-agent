# frontload 固定实验约定

候选：combat4r 首轮 N 后无存活终局，沿用原有追加 N；累计 2N 后无存活终局，在原树、原 RNG 上追加 2N，随后行动。后续预算仍按原规则分配。`fl1` 覆盖第一幕非 Boss；`flall` 覆盖第一至三幕非 Boss。第四幕、全部 Boss 排除。

正式运行包只读。候选路径为本工作目录和云端 `~/sts/runs/frontload-20260930/runtime-frontload`。驱动从云端 v21 复制为 v25。候选标识 frontload-20260930-v1；它不是并入老师的 fix 版本。

机制样本：traj-c42/traj-c43 的 3000 条轨迹；全部第一幕非 Boss 致死战斗 274 场；从 25231 场原胜战斗按 Python `random.Random(20260930).sample` 抽取 512 场。样本在候选搜索前冻结。历史轨迹合法动作与结局逐步核对；事件战斗由轨迹重建，以保留游戏回调，状态 JSON 用于哈希验证。

基线每状态一次搜索；候选每状态一次搜索；搜索结果和错误写入追加式文件。错误保留，不能归为死亡或胜利。上限先按机制样本基线最大单场访问量的两倍冻结；这保证相对于该基线最大值的绝对上限，不能保证每个新状态都小于其反事实基线访问量的两倍。报告另列配对访问量比例、超过实际两倍的数量、触顶数量。触顶后停止扩展，执行现存终局计划；没有终局计划则报错。用户对上限口径的澄清优先。

整局：3900012000–3900013999 共 2000 局，c42 合并开关加 fl1，各种子一次。胜负基准为冻结的 c42-merge.jsonl（1002/2000）。同种子基线另运行一次用于 CPU 测量和历史复现检查，不用它替换 c42 基准。基线和候选执行次序按种子奇偶交替；整局结果、轨迹、每场实际访问量和 CPU 秒保留。

2000 局结束前不按阶段胜率决定停止或更换参数。只有执行错误、来源漂移或资源冲突可以暂停；已产生的结果保留。发生漂移或错误时，统计完整性缺口单列，不能缩小验收分母。

胜率差：运行用户指定的 pair.py，以种子为配对单位，报告救回、被损、净变化和 95% 区间。补充种子级 bootstrap 区间，不把单场当作整局独立样本。

CPU：报告全部候选和计时基线的整局 CPU 均值、中位数、p90、p95、p99、最大值，以及配对均值差和比值的 95% 区间；报告单场 CPU 与墙钟耗时分布，含 p99。先将实用拖慢界限定为 5%；同时列出区间是否排除零，不将统计不显著当成性能等价。并入要求胜率差区间下界大于零、CPU 比值区间上界不超过 1.05，并无显著 CPU 上升、没有验收错误或历史漂移。

若 fl1 胜率差区间含零或为负，结论为不并入，不运行 flall 或扩种子。若 fl1 通过，依据净收益、耗时、控制组损害决定扩展范围。3900018000–3900018999 既是本次机制样本来源，又用于历史 c39/c43；即使按用户要求复核，必须标为复用开发种子，不能作为未见种子证据。

资源：nice 15；数值库 1 线程；frontload 工作进程最多 24。整局按 100 种子分批；每批记录 uptime、现有重进程数量与线程数，并预留其他流水线资源。蒸馏评估与 c49 并存时降低 frontload 并发；不改、不停其他任务或云资源。评估块 3900040000–3900041999 和锁定验收块不参与。
