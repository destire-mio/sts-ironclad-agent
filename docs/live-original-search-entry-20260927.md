# 原版战斗接入：reuse 搜索入口与逐动作验证

本轮补齐“原版战斗局面 → 当前 reuse 搜索 → 原版执行”的入口。整局评测完成数为 **0**。首战前的涅奥与路线使用固定诊断输入，因此首战记录不属于 `sims32+boss12+rest+reuse+svsel+svcard` 的整局样本。

## 改动与策略身份

`steam/native/live_combat_search.cpp` 增加 `plan_reusing(BattleContext, simulations, boss_multiplier)`。输入为原版导入的战斗对象，搜索在副本上调用未改动的 `combat_search::playoutReusing`，返回完整动作序列、终局预测及树复用统计。调用方保留自己的预测对象，每个原版命令执行后才推进一次对应的模拟器动作。

搜索预算为普通战斗每轮 32,000，Boss 每轮 384,000。复用发生在求解整场战斗的内部重规划轮次，执行原版动作时沿用求出的计划。出现已比较字段的分歧时清空剩余计划，从原版正常出牌边界重建，再调用同一搜索入口；这时旧搜索树也不再使用。

源引擎来自 `sts-rl-agent-tree-arena/runs/combat-tree-arena-20260927`，复制到本工作树的 `runs/live-runtime-20260927-v2/`。核心及父策略文件未改动：

自然首战有 16 个非终局检查点，比较玩家数值、牌堆顺序与牌属性、怪物状态和能力、意图、药水、遗物相关状态、合法动作，以及 6 条战斗 RNG，所比较字段没有分歧。第 17 个命令结束战斗，原始比较器报告 `battle_exit_requires_run_context`；当前比较器补充胜负对照，仍将奖励生成、战后治疗和整局状态列为覆盖缺口。

故障注入改变的是模拟器副本中的计数，原版没有被修改。这项记录证明检测、丢弃旧计划、导入实际状态和重新规划的执行链；它不代表发现了自然发生的游戏规则分歧，也不能估计分歧造成的胜率损失。

首次原版启动触及原有 90 秒期限，日志显示游戏处于资源加载阶段。入口的启动期限改为 300 秒。失败实例的清理结果为无残留进程，失败没有计入败局。

## 选牌界面

原版的选牌界面需要多条命令时，程序保留一个模拟器动作，按原版卡牌 UUID 找到选项，完成选择与确认后推进该动作。单牌选择与 Java 确认分开处理；没有候选卡身份时拒绝猜测索引。

控制夹具覆盖 Armaments、Headbutt、Burning Pact、Gambler's Brew 选择两张牌，以及选择零张牌。修复前，Gambler's Brew 按手牌升序点击，使原版弃牌堆为 `[Bash, Defend_R]`，模拟器为 `[Defend_R, Bash]`。原版保留点击顺序，模拟器的这类多选动作按手牌降序执行；桥接层因此改为按模拟器执行顺序发送点击。修复范围为动作翻译，没有更改原版规则或模拟器规则。

修复前证据位于 `runs/live-selections-20260927-v1/failed-case.json.gz`；修复后与离线回归结果见报告旁的 `live-original-search-evidence.json`。控制夹具的出现次数不能充当自然局发生频率。弃牌次序可能影响之后洗牌的结果，本轮没有测量该问题对胜负的影响。

## RNG 与完整状态的边界

每次命令响应校验 16 个持久随机源的导出契约，并以独立原版读取结果核对。战斗预测引擎使用 6 条 RNG。首战中 `MathUtils.random` 在 17 个命令后均变化；奖励生成还推进 card、potion、treasure RNG。它们的原始数值保留在日志，不能称为 16 条 RNG 的未来状态预测通过。

怪物与卡牌的全部私有字段、动作队列、部分选择状态仍存在比较覆盖缺口。程序不在原版待选牌或待执行队列上伪造一个正常出牌局面：若此时需要重建，记录接入错误，保留现场。普通 SL 的共享 RNG 恢复与本场重打功能没有纳入本轮验证。

## 整局评测的剩余接入

旧 `steam/live_model_bridge.py` 使用历史 `DT_MAP` 等描述符；当前父网络编码器使用 `AK_MAP` 等字段。对真实首层地图调用旧桥，复现 `AttributeError: module 'armG_train' has no attribute 'DT_MAP'`。当前父策略观察维数为 6,843，候选描述符维数为 807，不能替换常量名后就认为策略一致。证据为 `runs/live-outside-entry-audit-20260927.json`。

整局入口需要把原版路线、奖励、商店、事件、篝火与牌组选择编码成当前父网络输入，接入 P300 的 rest、svsel、svcard，并校验候选集合、卡牌变化与执行结果。之后补充战后整局状态、待选牌恢复和 SL 验证，才能开始 20 局统计。本轮没有用旧策略跑 20 局，也没有提供胜率、分歧影响排序或频率乘影响的估计。

本轮没有改动模拟器战斗规则或 P300 价值计算，因此没有新增需要重测的价值表条目。后续规则修复造成卡牌或怪物行为变化时，需要按实际影响范围重测。

原版运行使用本机已有 JAR、BaseMod、CommunicationMod 和固定帧逻辑采集工具，属于原版 Java 规则执行，运行配置含 Mod。所有命令、响应和分歧状态可按日志重放；没有生成视频。JAR、构建产物和运行目录不加入 Git。
