# 原版导入器与界面过渡修复

后续三个 live6 故障、钢笔尖计数复审与 live7 同种子诊断见 [后续修复报告](original-importer-followup-2026-10-01.md)。本报告及其验证记录保留首轮检查口径。

修复范围是 live5 保存的 32 个已分类故障，以及复审发现的 2 个红骷髅匿名动作。代码位于 `main` 的 `steam/`、`sim_patch/parity/` 和 `combat_engine/`。这批改动修复状态导出、动作导入和界面过渡；模型权重没有修改。旧冻结交付和历史批次记录保留，测试结果不能加入旧批次的整局统计。

## 回归与构建

CMake 从同一核心构建 `slaythespire`、`fightsim`、`live_combat_search`，构建脚本刷新扩展和运行包清单。live 入口复用核心的搜索头文件，删除分叉副本；`MapNode::addEdge` 提供外部定义，避免桥接扩展构建成功却在加载时缺符号。公共 `plan_reusing` 保留 P300 默认参数。当前 `main` 的候选盗贼评分及现有私有状态校验保留；本轮不构成候选策略的胜率验收。

原版导出新增 `cards_drawn`／`energy_wasted`，搜索导入保留这些统计以及战后 HP 遗物信息。实时规划要求统计齐全；缺字段的旧 parity 夹具可以做已有范围的回放，不能进入实时搜索。相同原始搜索根拒绝重复规划。无计数遗物的 `-1` 按原值导入，尼奥的 6843 维父策略输入与同种子 native 开局匹配。

本轮在 macOS arm64、Python 3.12 构建并加载三个扩展。`tests/` 与 `steam/tests/` 回归为 **211 passed、7 skipped**，其中桥接回归为 **95 passed**；C++ CTest 为 **2／2 passed**。fightsim 批量测试使用本机既有的两份 P211 轨迹；轨迹没有加入仓库，源哈希见 [验证记录](original-importer-repairs-2026-10-01.json)。缺少这些历史轨迹的 clone 应运行下面的桥接回归，不能宣称完整旧实验套件通过。

保存的 26 项原版场景在当前构建上作离线回归，覆盖武装、头槌、燃烧契约、多张赌徒、有手牌选零张赌徒、坚毅胜利确认，以及工具箱搭配多种开战遗物。另用当前 Java 源码运行 **6 项原版检查**：故障种子开局、红骷髅高血量、低血量、叠加金刚杵、红骷髅排在工具箱前、秘密传送门的后续点击。隔离实例退出后残留进程数为 0。

```sh
# 使用安装依赖的 Python 3.12 环境，从仓库根目录执行。
python scripts/assemble_runtime.py --jobs 3
LIVE_TEST_ENGINE="$PWD/runtime/engine" python -m pytest -q steam/tests
ctest --test-dir build/engine --output-on-failure
```

原版夹具回放不需要游戏资产。新增原版检查需要用户提供的许可游戏、Mod 配置与本机 oracle；[验证记录](original-importer-repairs-2026-10-01.json) 保存编译后探针和源码哈希。CMake 生成的运行包可执行 native 桥接与回归；完整局外父策略还需要既有冻结 P300 bundle，`live_original/` 的路径适配限制见 [PORTING](../live_original/PORTING.md)。

## 证据范围

确认检查、保存状态回放、原版受控场景和启动检查证明各自覆盖的行为。原版／native 未观察的队列、事件私有字段、共享 RNG 等缺口保留在 comparator 的 gaps 中。十份缺少能力元数据的历史快照无法恢复目标和能力对象；新导出器与新扩展需要配套使用。

本轮没有未使用种子的自然整局验收，没有原版胜率提升结论。live6 的冻结交付和旧批次没有被改写；仓库发布不代表旧运行进程载入修复代码。
