# 商店选牌后的未领取奖励

本轮修复一处原版差异：购买星系仪，领取五组卡牌奖励中的两组，返回商店购买瓶装火焰并选牌后，原版显示余下三组奖励，模拟器返回商店。原版可以从这些奖励中获得卡牌，然后返回商店。修复恢复这条路径，并限定奖励缓存的房间生命周期。

## 根因与修复

原版 `AbstractDungeon.closeCurrentScreen` 在关闭 GRID 时检查 `combatRewardScreen.rewards`；只要列表非空，就把返回目标设为奖励界面。商店的瓶装选牌同样受这条规则影响。旧模拟器执行购买时设置的回调，回到商店，后续领取卡牌动作因此非法。

[shop_rewards.patch](../shop_rewards.patch) 接在 `relic_defaults.patch` 后，修改 `GameContext.cpp`。商店选牌执行原有返回回调后，若结果是商店且同房间的奖励非空，则显示这些奖励，并按值保存商店退出回调。完成奖励后返回商店，离店后进入地图。处理放在共同返回入口，购买遗物、完成删牌和取消删牌复用该规则；没有增加持久标记。

原版在进入下一房间时清空奖励界面。模拟器的奖励容器原来保留旧值，因此修复在 `enterMapRoom` 清空上一房间的缓存，避免旧奖励被新商店的选牌入口恢复。这个修改没有改变战斗规则或奖励生成算法。

## 独立原版证据

[十九个场景](specs/shop_continuation_round28.json)使用独立 JVM，输入是购买前声明的库存、牌组、遗物、金币、生命、遗物池和十组 RNG。库存生成在测试边界之外；原版验证上架遗物的 `canSpawn()` 和商店专属槽位。场景不代表自然商店生成或新种子胜率。

捕获包含 21 次遗物购买、9 次瓶装选牌、116 个检查点和 149 条原版命令。模拟器从配对初态执行 97 个动作，后续原版状态不进入模拟器。比较覆盖钱包、生命、牌组、遗物与计数、药水、剩余奖励、选牌候选、库存与价格、可购买遗物槽位和十组 RNG。97 次副本检查核对父状态不变及副本结果一致，范围为序列化观察字段。

对照包含三种瓶装遗物、快递员补货、会员卡折扣、大锅、添满药水后弃药领取、添水不让获得药水、歌唱碗、关闭重开奖励、金币恰好够买与差一块、Maw Bank 消费后失效、反向购买顺序，以及领取星系仪全部奖励后购买瓶装遗物。后两组区分“有未领取奖励”与“打开过奖励界面”这两种解释。

旧版在完整十九场景中得到 `coverage_gap: 18`、`worker_error: 1`，失败原因是选牌后处于商店，无法执行原版后续领奖动作。失败命令之前的原版前缀保留了四处状态分歧：界面、合法遗物槽位、卡牌奖励与奖励顺序。修复后的生产和观察构建得到 `coverage_gap: 19`，所比较字段吻合。报告没有把这些场景标为全量通过。

## 命令映射与观察边界

预检驱动曾把商店关闭后的 `SHOP_ROOM` 当成游戏内部的 `NONE`，并使用通信插件报告的 `proceed` 退出遗物奖励。原版奖励界面实际显示返回按钮；插件的 `proceed` 会显示隐藏的前进按钮并打开地图。驱动改用现有 oracle 的 `cancel_shop_reward`：它检查原版按钮可见，再点击该按钮的 hitbox，由原版执行关闭流程。需要时通过商人选项重开库存。

领取全部奖励后完成瓶装选牌，再关闭商店，原版可能恢复空奖励界面。捕获保留这个中间状态，使用该状态下通信插件提供的 `proceed` 到地图。它与模拟器的离店动作按最终状态对应；隐藏按钮、界面中间帧和完整合法 UI 域没有获得一致性结论。[映射记录](../../runs/parity-20260928/round28-shop-continuation-tools/empty-return-mapping.json)说明这个限制。六个失败捕获保留，未算作通过。

本轮抽出共享奖励观察函数，并拆分 Java 初态设置。十七个旧宝箱场景回归通过；其中一个场景使用新 JVM 捕获，初态、遗物池、命令和比较状态与旧捕获相同。原版 UUID、表现随机源与其他私有字段不在这个相等结论内。
