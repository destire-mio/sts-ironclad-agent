# 宝箱、套娃与蓝宝石钥匙

本轮增加 17 个独立原版场景、95 个检查点。所比较的行为字段吻合，没有证实新的规则缺陷。改动包括原版宝箱观察入口、模拟器观察器、命令映射和验收；规则核心沿用 R9 默认遗物计数修复版本。

## 范围与独立输入

每个场景使用独立 JVM，参考为安装的 Java 游戏及配置的 Mod。输入在宝箱生成前设置：牌组、遗物与计数、生命、金币、钥匙、符合稀有度的遗物池以及十组 RNG。种子筛选用于寻找不同宝箱大小、金币与遗物分支，原版实测负责确认结果。场景为受控机制测试，不构成自然整局样本。

原版使用普通命令开箱、领取奖励、完成瓶装选牌和离开，共 78 条命令。模拟器从配对初态执行相同语义的动作，没有导入原版后续状态。观察内容包括宝箱类型、掉落分支、十组 RNG、牌组、遗物、药水、生命、金币、钥匙、剩余奖励、选牌候选及奖励生成器状态。

原版的蓝宝石钥匙通过对象引用指向某件遗物。观察器读取这个引用，并记录它在剩余遗物中的位置。模拟器从自身 `sapphireKey` 和遗物数组生成对应观察，避免拿原版关联填充模拟器结果。

## 检查结果

覆盖三种宝箱大小，以及先领套娃额外遗物再换钥匙、先换钥匙再领额外遗物、领取额外瓶装遗物后换钥匙、领取与钥匙关联的瓶装遗物等顺序。两次瓶装选牌后的剩余奖励和钥匙关联吻合。

恩洛斯的饥饿面具与套娃组合保留基础遗物及其钥匙；没有套娃时，面具移除基础遗物及钥匙。两种遗物排列顺序、套娃最后一次次数、耗尽状态、失效面具、已有蓝宝石钥匙和放弃奖励的对照通过比较。

诅咒钥匙配合御守、黑石护符及陶瓷小鱼的牌组、计数、生命上限、金币与 RNG 变化吻合。金神像不增加宝箱金币；鲜血神像在领取金币时回复 5 点生命。两种神像分开测试，鲜血神像和已有蓝宝石钥匙的初态放在第二幕，避免把正常流程中互斥的神像放在同一场景。

78 个模拟动作包含复制检查：在副本中执行后，父状态的被观察字段不变；副本结果与未复制分支一致。该结论限定于观察器序列化的字段。

## 原始差异与检查器修正

报告为 `coverage_gap: 6`、`observation_difference: 11`。11 个场景保留 36 处奖励顺序字段差异。原版界面按房间中的列表顺序显示奖励；native 按类型保存数组，观察器按类型输出。分类要求每种奖励的内容、同类顺序和钥匙关联全部吻合，只将跨类型排列归为表示差异。改变同类顺序、关联位置或奖励内容不能获得该豁免。原版界面顺序没有被删改，报告不代表 UI 逐帧一致。

首版 native 观察器在宝箱打开后输出 `chest: null`，原版 Gson 会省略这个字段，导致四个初始报告出现多余字段差异。修正为两边都只在未开箱阶段输出宝箱信息；原版捕获和规则代码没有改动。首版二进制、输入、差异报告及[修正记录](../../runs/parity-20260928/round27-treasure-tools/observer-correction.json)保留。
