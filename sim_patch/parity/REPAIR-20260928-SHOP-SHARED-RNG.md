# 商店共享随机数与界面初态

14 个独立原版场景、58 个检查点证实：只配对牌组、钱包和 `MathUtils` 初始种子不足以重现有色牌快递员补货。修复提供一次性导入界面初态、按声明帧数推进的 native 入口。生产和观察构建在本轮范围内消除 122 处规则字段分歧，其中 12 个场景包含补货牌身份分歧。完整一致性为 `INCOMPLETE`。

## 反例

持有快递员，连续购买同一攻击牌槽。原版和旧模拟器第一次补货为交锋，第二次原版为以血还血，旧模拟器为残杀。原版购买音效、商人对话、获得卡牌的动画、商店漂浮动画和抖动文字共用 `MathUtils`；旧模拟器处理了购买音效及补货抽样，没有推进后续界面消费。

把商店停留 600 帧后配对相同的公共游戏状态与随机状态，第二张原版补货变为飞身踢。变化来自界面初态中的漂浮位置。另一组保持初态相同，把两次购买之间的观察间隔从 31 帧改为 64 帧，第二张补货同样改变。抖动文字场景一次购买可以消耗数百次随机数，因此固定补几个随机调用不能解决问题。

带调用栈记录和没有记录的原版对照在游戏、随机数和所比较界面字段上相同。增加帧计数观察器前后的对照相同。七份诊断捕获及其旧代码、二进制保留；正式夹具使用带环境字段的 14 份新捕获。

## 修复与输入边界

`GameContext.attach_shop_presentation(state, seed0, seed1)` 接收购买前的状态：漂浮位置和速度、商人对话计时、文字效果及其计时、五条本地化购买台词、共享随机状态，以及预先声明的每次购买帧数。输入只在首个购买前设置，重复附加被拒绝。`shop_presentation` 暴露所建模状态，副本以值持有其文字和计时数据。

生产 `Shop::buyCard` 调用原版顺序对应的界面推进：本帧漂浮和旧对话更新、购买音效与补货、购买台词及卡牌获得动画随机调用、后续帧的文字更新与渲染。抖动文字的更新与渲染分别取随机数；中文按 UTF-16 字符分词。浮点运算保留 Java 的 float32 分步舍入，比较器核对位表示。离开商店时处理关闭前的更新和地图打开音效。

本轮入口要求安装的固定帧参考、前台、快速模式、每帧 1/60 秒、初始逻辑效果完成、没有待领奖励及未完成的初始文字解析。帧数范围为 31–240，本轮原版覆盖 31 和 64。允许的持有遗物为燃烧之血、快递员、会员卡和三种蛋；其他回调、药水／遗物／删牌购买在启用该入口时拒绝执行。自然初始库存、其他帧节奏、其他回调、存档恢复及无 Mod 参考保留缺口。

没有附加这些输入的历史模拟路径保持其行为，不能据此宣称共享随机数精确一致。输入缺失不能通过填入原版后态补齐。本轮模拟器输入不包含后续原版随机数、调用栈、抽样次数或库存；删除／伪造未来调用栈不改变 native 输入或结果。

原版购买由 CommunicationMod 的普通命令执行。额外等待的目标帧数在动作前声明；观察器只调用游戏原有渲染循环到该帧，若动作耗时超过声明值或逻辑效果没有完成则报错。它不修改随机数、库存、卡牌或商店规则。三个旧帧场景与新 31 帧场景的公共游戏和随机数结果相同。

- 14 个原版场景、58 个检查点、44 个 native 动作及父副本隔离检查；原版包含 58 条普通命令和 30 次声明帧观察。覆盖两种等待时长、不同初始漂浮位置、横纵边界、两类抖动台词、技能／攻击／能力／无色牌组合、蛋类升级和会员卡折扣。
- 15 个错误状态／初态反例、27 个缺失或不支持输入被拒绝。生产 Python 入口验证错误输入不改变状态、重复附加不能同步随机数。
- 457 个 CTest 入口通过，包含历史 1002 条自然整局命令、837 个有差异字段记录的检查点；终局为第 51 层失败，分数 1786。这是历史回放，不是新种子胜率评估。
- 生产、观察和搜索模块采用同一规则源码；八个搜索任务的顺序、单线程批处理和四线程批处理结果相同，输入状态及 RNG 保持原值。两个便携源码变体补丁零 fuzz 应用，各四个修改编译单元通过语法检查。
