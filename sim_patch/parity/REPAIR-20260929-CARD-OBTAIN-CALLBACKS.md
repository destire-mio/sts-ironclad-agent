# 获得卡牌回调的执行时机修复

商店买牌、奖励领牌和多利之镜复制卡牌时，模拟器把获得卡牌的遗物回调放到了错误的动画更新阶段。陶瓷小鱼配合鲜血神像、黑石护符等组合会因此改变回血效果消费的共享随机数，造成后续快递员补货分歧。御守抵消诅咒时还会多消费一次入牌动画的随机数。本轮修复这三条路径，保留原版捕获与修复前对照。

适用范围为安装的 Java 原版及 Mod、配对的初始界面状态和声明的动作帧数；完整一致性状态为 `INCOMPLETE`。工作位于 `codex/original-simulator-parity-20260927` 隔离 worktree，未提交、推送或修改主工作树。用户撤销了暂停要求，goal 为 active。

## 改动与依据

原版商店将 `FastCardObtainEffect` 放入顶层效果列表，先处理购买语音和已有顶层效果，后调用获得卡牌的遗物回调，再处理普通效果。奖励领牌通过普通效果队列调用回调；多利之镜的回调发生在复制动画的后续更新中。旧模拟器在前两条路径中提前执行 `deck.obtain`，在镜子路径中又把回调产生的回血效果留到了下一帧。

修复拆开顶层效果更新、普通效果更新和回血队列入列三个阶段，在原版对应的位置调用既有获得卡牌逻辑。新入列的回血效果参与当前帧渲染，从下一帧更新寿命。复用 `installed-shop-v5/v6` 状态结构，没有增加新配置版本或可变数据字段。

原版在复制诅咒效果的构造阶段消耗御守，取消后不进入获得卡牌回调或 Soul 入牌动画。模拟器按这一分支扣除御守次数、跳过卡牌与遗物回调、跳过对应随机消费。初始御守次数要求为 0 至 2；拒绝输入前不改变游戏、共享 MathUtils RNG 或 Collections RNG。

[补丁](../card_obtain_callbacks.patch)接在 `shop_upgrade_rng.patch` 后。[分发清单](../alignment/card-obtain-callbacks-manifest.json)绑定四个核心文件；核心、Python 绑定、观察构建及搜索模块均完成构建。既有 `Deck.obtain` 中黑石护符与陶瓷小鱼的固定检查顺序没有调整；两个持有顺序的样本验证本轮比较字段，不构成所有回调交换顺序等价的结论。

## 原版对照

正式证据包含 18 个场景、95 个检查点、77 个 native 动作与 102 条普通原版命令。各场景使用独立 JVM；模拟器接收初态、普通操作和预先声明的时钟，后态、逐次随机轨迹和采集帧记录不参与推进。

样本覆盖买牌与奖励领牌，陶瓷小鱼单独持有及搭配鲜血神像，黑石护符与两种遗物持有顺序，御守有次数／耗尽时复制诅咒，巫毒娃娃计数，禁疗、灵体外质、满血，以及删牌／升级动画与领牌效果重叠。两份镜子早期样本实际选中旋风斩，保留为非诅咒对照；诅咒样本依据原版选择列表中的痛苦身份选取。开启／关闭随机轨迹的一组原版对照输出相同。

定位原因的旧版对照只扩大已有界面配置允许持有的六种遗物，不修改回调规则或时序；它与已验收的 R17 运行时有区别。该对照中 12 个场景有分歧，6 个场景吻合。修复后生产和观察构建的 18 个场景比较字段吻合，两种构建输出相同。

前后消除 4251 处字段差异，其中含回血粒子私有字段，不代表 4251 个缺陷。10 个场景涉及后续库存反例。[分类记录](../../runs/parity-repair-20260929-card-obtain-callbacks/classification.json)与[隔离说明](../../runs/parity-repair-20260929-card-obtain-callbacks/scope-isolation.json)保留统计与来源。

## 失败与边界

共启动 20 个原版实例。早期两例把多利之镜放入不允许商店专属遗物的槽位，原版在建立初态时拒绝，保留为 `original_error`，没有检查点证据；修正槽位后使用新 JVM 捕获。原型 v1 的御守校验误覆盖禁疗遗物，导致一例 `worker_error`；失败原型、报告和修正后的 v2 分开保留。失败记录不计为通过，也不计为原版规则缺陷。

18 例的最终分类为 `coverage_gap`。自然商店入口、任意帧节奏、其他遗物回调、未投影的视觉内容与私有字段、完整药水动作域和无 Mod 原版保留缺口。后续排查沿持续清单推进，不能用这些有限样本保证不存在其他差异。
