# 事件战斗胜利、奖励生成与领取

本轮增加 26 个独立原版场景，覆盖死亡冒险者、蒙面强盗、神秘球体、心灵绽放和蘑菇事件的战斗结束、奖励生成、领取与离开。比较范围内没有发现新的规则缺陷；运行时使用上一轮默认遗物计数修复的核心源码。本轮改动检查器、观察入口和验收，不修改规则源码。

## 独立输入与动作

每个场景使用独立 JVM，参考为安装的 Java 游戏及其 Mod。受控输入包括事件前牌组、遗物、生命、金币、遗物池及九组 RNG；药水概率修正为 0、卡牌稀有度修正为 5，A20 各幕升级概率为 0／0.125／0.25。模拟器从这些初态执行事件和动作，不导入原版后续状态。

16 个场景对应历史奖励样本，另有 10 个对照：三个手里剑场景，白兽雕像配合添水／鲜血神像的三个药水场景，三个不使用哀嚎的灼热攻击 +10 场景，以及放弃全部奖励。其余场景用哀嚎和旋风斩完成战斗。牌组与遗物为机制测试输入，不构成自然整局或自然胜率证据。

原版通过 57 条事件命令、34 条战斗命令和 122 条奖励 UI 命令，形成 26 个事件前状态、157 个后续检查点。领取一张卡在原版分为打开奖励和选择卡牌，模拟器是一条动作；对应原始 UI 中间帧保留，131 条 native 动作不表示 UI 逐帧一致。原版胜利执行普通游戏回调，没有使用旧夹具的 `room.phase=COMPLETE` 快捷路径。

## 结果与反证

比较范围包含九组 RNG、有序战斗牌堆、生命／能量／格挡、八种玩家能力、怪物生命／力量、战斗合法动作、主牌组、遗物、药水、奖励内容及奖励生成器状态。26 场景的这些行为字段吻合。金神像加钱、重复遗物变为头环、卡牌升级、金币和卡牌领取、离开奖励通过比较。

手里剑在事件战斗胜利后恢复为 −1。白兽雕像产生药水奖励；持有添水时，领取动作移除奖励但不增加药水。这与原版 `RewardItem.claimReward` 的返回值及模拟器处理一致。

原始分类为 `observation_difference: 26`，其中保留 37 处哀嚎／手里剑战斗内计数差异和 6 处死亡史莱姆老大记录差异，不能称为完整原始状态一致：

- 战斗内原版计数与模拟器主进程持有的计数归属不同。检查器保留两边实际值，只在源码支持的精确关系成立时分开分类；手里剑关系还核对 native 战斗状态中的本回合攻击次数。
- 史莱姆老大分裂后，原版保留死亡 Boss 的名称和最大生命；native 在两个子怪物之间留空槽。项目已有 `canonical_monsters` 处理这一布局。三个检查点的名称／最大生命差异保留；活怪、合法动作、后续击杀和奖励吻合。分类限定于空槽、原版死亡 Boss、初始 native Boss 最大生命及两个子怪物身份的精确对应，其他差异不豁免。

首次控制组比较暴露两个分裂怪物名称映射缺口，报告保留 `adapter_error`。补齐映射后得到上述六处原始差异；源码审查和既有目标映射说明其状态表示边界。没有为让报告通过而改写原版捕获，或给 native 空槽填入原版后续值。
